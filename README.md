# Wine Quality: подборка хороших вин

Streamlit-приложение к ДЗ 3. Модель оценивает вероятность экспертной оценки вина не ниже 7. Внутри приложения обучение не выполняется: загружается готовый пайплайн `StandardScaler → LogisticRegression` из ноутбука.

## Запуск

Проверено с **Python 3.12.14**. Для воспроизведения используйте Python 3.12 и закреплённые зависимости:

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
streamlit run app.py
```

На Windows вместо `source` выполните `.venv\Scripts\activate`.

Запускать можно из любой папки, указав полный путь к `app.py`. Модель, конфигурация и тестовая таблица ищутся относительно `Path(__file__).resolve().parent`, а не текущей рабочей папки.

Рядом с `app.py` должны лежать:

| Файл | Содержание |
|---|---|
| `model.joblib` | Обученный пайплайн целиком, включая масштабирование |
| `config.json` | Рабочий порог в поле `threshold`, выбранный на валидации |
| `test.csv` | Тестовая выборка с 12 признаками и целевой меткой `target` |
| `requirements.txt` | Проверенные версии зависимостей |
| `example_wines.csv` | Пример входного CSV без целевой метки |

Файлы `model.joblib`, `config.json`, `test.csv` создаёт ячейка сохранения модели в выполненном ноутбуке. Загружайте только собственные доверенные файлы моделей: формат joblib использует Python pickle.

## Что умеет приложение

1. **Оценить вино.** Ввод 11 лабораторных показателей и переключатель «Красное вино». Начальные значения — медианы `test.csv`, допустимые диапазоны — её минимумы и максимумы. После отправки формы показываются вероятность и решение.
2. **Модельные метрики.** Precision, recall, F1, размер подборки, матрица ошибок, ROC- и PR-кривые. На обеих кривых отмечена точка текущего порога. Горизонтальная линия на PR-графике соответствует доле хороших вин.
3. **Загрузить CSV.** Пакетное предсказание, таблица и скачивание результата. Слайдер в сайдбаре общий для всех вкладок. Кнопка возвращает рабочий порог из конфигурации.
4. **Что выучила модель.** Отсортированные коэффициенты после масштабирования и признаки с наиболее положительным и отрицательным вкладом. Коэффициенты описывают связи в модели, не причинность.

Тестовая выборка используется для оценки качества. Ползунок демонстрирует компромисс между ошибками; рабочий порог выбирается на валидации в ноутбуке, а не по показанным тестовым метрикам.

## Формат CSV

Обязательные числовые столбцы:

```text
fixed_acidity,volatile_acidity,citric_acid,residual_sugar,chlorides,free_sulfur_dioxide,total_sulfur_dioxide,density,pH,sulphates,alcohol,is_red
```

`is_red` принимает только 0 (белое) или 1 (красное). Порядок столбцов может быть любым: перед предсказанием приложение приводит его к порядку модели. CSV с разделителем `,` или `;` поддерживается. Столбец `target` во входном файле не нужен.

Если отсутствуют обязательные столбцы, есть пустые/нечисловые/бесконечные значения или неверное значение `is_red`, приложение выводит понятную ошибку. Дополнительные столбцы сохраняются в результате, но не передаются модели. Числовые значения за пределами наблюдавшихся диапазонов вызывают предупреждение.

Выходные столбцы:

| Столбец | Значение |
|---|---|
| `probability_good` | Вероятность класса 1 |
| `prediction` | 1, если вероятность не ниже выбранного порога, иначе 0 |
| `decision` | «Рекомендовать» или «Не рекомендовать» |

## Кэширование — ответ на задание 4.5

`load_model` использует **`st.cache_resource`**: модель — ресурс, один объект которого можно совместно использовать при повторных запусках и в разных сеансах. Мы не изменяем её и не вызываем `fit` в приложении. Модель не загружается через `st.cache_data`.

`load_test_data`, `test_proba` и расчёт кривых используют **`st.cache_data`**: таблицы и массивы — данные. Streamlit сериализует кэш и возвращает отдельные копии, что защищает кэш от случайного изменения получателем.

`test_proba(_model, X, model_stamp)` не зависит от порога. Подчёркивание исключает модель из хэширования, а версия файла `model_stamp` позволяет корректно обновить вероятности при замене модели. При движении слайдера пересчитываются сравнение с порогом и зависящие от него метрики; `predict_proba` на тестовой таблице повторно не вызывается. Примеры из формы и загруженные CSV — отдельные новые входные данные.

Без декоратора `joblib.load` заново читал бы и восстанавливал модель при каждом взаимодействии, увеличивая время отклика и нагрузку. Без кэша тестовых вероятностей выполнялись бы и лишние предсказания.

Официальная документация: [`st.cache_resource`](https://docs.streamlit.io/develop/api-reference/caching-and-state/st.cache_resource), [`st.cache_data`](https://docs.streamlit.io/develop/api-reference/caching-and-state/st.cache_data).

## Проверка

Из корня решения (уровнем выше `wine_app`) можно запустить автоматические проверки:

```bash
python -m pip install pytest
python -m pytest tests/test_streamlit_app.py -q
```

Проверяются запуск всех вкладок, граничные пороги 0 и 1, общее состояние порога, возврат рабочего порога, отсутствие повторной загрузки модели и повторных тестовых предсказаний при движении слайдера, ввод одного вина и проверка CSV. `AppTest` не поддерживает установку загруженного файла, поэтому разбор CSV дополнительно проверяется напрямую через чистую функцию `parse_batch_csv`.

## Streamlit Community Cloud

Для публикации нужен GitHub-репозиторий и аккаунт Streamlit Community Cloud:

1. Добавьте содержимое `wine_app/` в репозиторий, включая `model.joblib`, `config.json`, `test.csv` и `requirements.txt`.

4. После успешного запуска откройте опубликованный адрес, проверьте вкладки и вставьте этот адрес в ноутбук.

Сам по себе локальный запуск или наличие архива не является публикацией. Публичный URL нужно получить после реального деплоя.

Официальная инструкция: [Deploy an app on Streamlit Community Cloud](https://docs.streamlit.io/deploy/streamlit-community-cloud/deploy-your-app/deploy).
